# 《原神·星铁》智能旅伴 — 设计规格说明书

> 基于 [《原神·星铁》智能旅伴 功能开发计划书](../../../《原神·星铁》智能旅伴%20功能开发计划书.md) 深化细化，经 brainstorming 确认的最终设计。

## 一、项目定位

Windows 11 桌面小工具，围绕截图、抽卡记录、游戏时长构建个人游戏生涯管理。

**红线原则：**
- 绝不读取/修改游戏内存，不注入进程，不 hook API
- 不模拟键盘鼠标，不自动操作游戏
- 仅对用户手动截图进行 OCR，不自动截取游戏画面
- 网络请求仅当用户主动使用云同步时发生，其他完全离线

## 二、UI 设计

### 2.1 整体布局

- 顶部导航栏（透明毛玻璃）: 应用名 + 页面标签 + 用户头像占位
- 主内容区: 卡片式布局，白色圆角卡片 (border-radius: 12px)
- 无左侧导航栏，保持简洁

### 2.2 配色方案（游戏可切换）

**统一基础色：**
- 页面底色 `#FAFAF7`（原神）/ `#F5F7FA`（星铁）
- 卡片底色 `#FFFFFF`
- 主文字 `#1a1a2e`
- 次级文字 `#8b7a64` / `#9a9a9a`

**原神模式（派梦印象）：**
- 主色 `#D4433B`（派梦红）
- 金色 `#C89B3C`（5⭐标识）
- 顶部渐变色条 `#D4433B → #C89B3C`

**星铁模式（帕姆印象）：**
- 主色 `#3D5A80`（帕姆深蓝）
- 金色 `#C89B3C`（5⭐标识）
- 顶部渐变色条 `#3D5A80 → #C89B3C`

**语义色（两模式共用）：**
- 绿色 `#22c55e` — "欧了"
- 红色 `#D4433B` — "歪了" / 警示
- 金色 `#C89B3C` — 5⭐标识

### 2.3 游戏切换交互

顶部 pill 式分段控件：
```
[ ⛰️ 原神 | 🚂 星铁 ]
```
选中项白底浮起 + 阴影，未选中灰底。切换时以下元素随游戏换色：
- 页面底色（暖白/冷白）
- 操作按钮颜色
- 顶部渐变色条
- 统计数据中的游戏标识

### 2.4 主题模式

仅浅色模式，不支持深色模式。

## 三、功能模块

### MVP 范围（三个模块）

#### 3.1 抽卡记录自动解析 + 本地战绩库（核心功能，最优先）

**输入：** 用户对游戏内「抽卡记录」页面的截图

**处理流程：**
1. **特征识别** — 检测截图是否为抽卡记录页
   - 原神：识别"历史记录"标题 + 纠缠之缘/相遇之缘图标
   - 星铁：识别"跃迁记录"标题 + 星轨通票/星轨专票图标
   - 方法：裁剪特征区域 + 颜色直方图比较（用 `image` 库，不用 `imageproc`）
2. **区域切分** — 将每行记录（日期、物品、星级）切分为独立小图块
   - 固定比例切割或基于淡色分隔线检测
3. **OCR 文字提取**
   - 调用 Windows.Media.Ocr（Windows 内置 OCR，支持中文）
   - 通过 `windows-rs`（`Windows::Media::Ocr`）调用
   - 在异步任务中执行，不阻塞 UI
4. **物品名规范化**
   - "七七" / "七七·角色" → "七七"
5. **去重入库**
   - 按 日期+物品+星级 比对 SQLite 数据库去重

**本地战绩库 UI：**
- 列表视图：按时间倒序展示所有抽卡记录
- 统计卡片：累计抽数、5星数量、平均出货间隔、当前保底计数
- 欧非曲线：ECharts 图表，横轴抽数，纵轴出货标识
- 歪卡标识：歪了的 5⭐ 特殊标注
- 数据导出：CSV / JSON

**存储占用：** 约 50 字节/条，10 万条约 5 MB

#### 3.2 游戏时长与活跃度记录

**原理：**
- 周期扫描进程列表，匹配 `YuanShen.exe` / `StarRail.exe`（`sysinfo`）
- 获取当前前台窗口进程名，仅前台时计时（避免挂机虚高）
- 通过 `windows-rs` 的 `GetForegroundWindow` / `GetWindowThreadProcessId`

**记录粒度：** 按天、按版本周期统计

**版本周期：** 内置或手动编辑游戏版本起止日期表

**可视化：**
- 日/周/月热力图（类似 GitHub 贡献图，ECharts 实现）
- 各版本平均在线时长对比柱状图

**存储占用：** < 1 MB/年

#### 3.3 截图智能策展

**在已有截图管理基础上增强：**
- 自动标签生成：
  - 抽卡截图 → 标签"抽卡记录"
  - 场景图 → OCR 识别底部/顶部区域名（"璃月港""黑塔空间站"）
  - 成就弹出 → 识别成就名称 → 标签"成就"
- 智能搜索：搜索"深渊" → 列出所有场景含"深境螺旋"或成就含"深渊"的截图
- 实现：新增截图后台异步处理，不阻塞主线程

**存储占用：** < 1 KB/张截图元数据，1 万张约 10 MB

### 后续迭代（非 MVP）

- 角色面板练度 OCR（识别属性面板数值）
- 体力/派遣轻提醒（Toast 通知 + 定时器）
- 云同步（WebDAV / OneDrive）
- 更丰富统计报表（资源台账等）

## 四、数据存储

### 4.1 文件结构

```
AppData/
├── companion.db               # SQLite：抽卡记录、游戏时长、版本定义
├── screenshot_index.db        # 截图元数据（路径、标签、OCR 文本等）
├── config.json                # 用户设置（提醒间隔、版本日期）
└── thumbnails/                # 可选缩略图缓存
```

所有数据存于工具自己的目录，卸载直接删除。

### 4.2 关键技术约束

- 数据库连接池：`r2d2` + `r2d2_sqlite`（不直接用 `Mutex<Connection>`）
- 所有数据库操作在 `spawn_blocking` 中执行（`rusqlite::Connection` 非 Send）
- Rust → 前端返回值统一 `#[serde(rename_all = "camelCase")]`

---

## 五、安全配置

- `tauri.conf.json` 默认关闭 `shell.open`，不开启危险权限
- CSP: `default-src 'self'; img-src 'self' asset: https://asset.localhost; style-src 'self' 'unsafe-inline'`
- 所有网络请求仅当用户主动使用云同步时发生
